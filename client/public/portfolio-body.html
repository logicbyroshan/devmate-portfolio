9 Core Engineering Components

Role-based architecture (Owner, Admin, Assistant, Operator) strictly governing permissions for view, create, edit, verify, approve, download, and user administration.

3. Workflow Management

Explicit lifecycle transitions making it possible to track progress across large datasets with complete administrative visibility.

4. Audit Logging Layer

Records who performed an action, what operation occurred, affected record, timestamp, and field-level diffs for full organizational compliance.

Imports CSV, XLSX, and ZIP photo datasets with automatic schema validation; exports XLSX, CSV, print-ready PDF, and DOCX outputs.

6. Photo Pipeline

Dedicated processing for student & relationship photographs, missing photo indicators, and auto-cropping to prevent misprinted physical cards.

7. Background Processing

Celery + Redis workers offload heavy image manipulation, PDF compilation, and large imports from the synchronous HTTP request thread.

8. REST API Architecture

Django REST Framework API-first backend providing centralized endpoints for auth, cards, workflows, and batch operations across all clients.

9. Cross-Platform Ecosystem

Shared backend logic serving React Web, Electron Desktop, and React Native Android clients with identical business rules.

5 Real Engineering Challenges Overcome

1. Large Dataset Operations

Users needed to search, filter, sort, verify, and approve 136K+ card records without UI lag. Solved via database indexing, query optimization, and bulk SQL updates.

2. Multi-User Operations & RBAC

Prevented unauthorized operations across organizations with an explicit permission matrix enforced at both API serializers and service layers.

3. Long-Running Operations

Moving multi-thousand record exports and photo calibrations into Celery background workers decoupled user actions from HTTP response timeouts.

4. Source Data Quality & Deduplication

Implemented checksum duplicate detection and pre-generation validation checks to eliminate missing photographs and corrupt rows before printing.

5. Real Production Reliability

Refined error handling, graceful fallback for malformed spreadsheets, and seamless rolling updates on production Linux servers.

Key Architectural Decisions

Why Django & DRF?

Provided a mature ORM, built-in security protections, robust admin interface, and standardized REST API endpoints for multiple client platforms.

Why PostgreSQL?

Strict ACID guarantees, relational integrity for multi-tenant data, fast B-tree indexing on search fields, and battle-tested production reliability.

Why Redis & Celery?

Eliminated web request blocking during heavy image finishing, PDF compilation, and bulk imports by queuing tasks in background workers.

Why API-First Architecture?

Allowed React Web, Electron Desktop, and Android to share identical business rules, validation schemas, and database transactions.

Understanding Microservices Architecture: A Developer's Guide

R
Roshan Damor
November 15, 2024

Microservices architecture has become one of the most talked-about patterns in modern software engineering. Unlike traditional monoliths where the entire app resides in a single codebase, microservices decompose systems into independent, specialized domain services.

Core Principle
Each microservice must own its database exclusively. Direct cross-database queries between services are strictly prohibited to prevent tight coupling.

Entity Relationship & Microservice Boundaries

Here is an architectural ER Diagram illustrating isolated database schemas across distinct domain microservices:

Database ER Diagram & Domain Seams
PostgreSQL / Redis
USERS_DB.users
  • PK id UUID
  • email VARCHAR(255)
  • password_hash TEXT
  • created_at TIMESTAMP
ORDERS_DB.orders
  • PK id UUID
  • FK user_id UUID
  • total_amount NUMERIC(10,2)
  • status ENUM
PAYMENTS_DB.txns
  • PK txn_id UUID
  • FK order_id UUID
  • stripe_charge_id VARCHAR
  • paid_at TIMESTAMP

Implementation Step-by-Step

1
Domain Decomposition
Identify clear domain boundaries using Event Storming to extract bounded contexts.
2
API Gateway Routing
Set up an API Gateway (Kong, Traefik, or Nginx) for single-entry routing and SSL termination.
3
Asynchronous Event Bus
Connect RabbitMQ or Kafka for event-driven messaging between independent services.

Service Implementation

user-service/index.jsJavaScript
const express = require('express');
const app = express();
app.use(express.json());

app.get('/users/:id', async (req, res) => {
  const user = await UserRepository.findById(req.params.id);
  if (!user) return res.status(404).json({ error: 'Not found' });
  res.json(user);
});

app.post('/users', async (req, res) => {
  const user = await UserRepository.create(req.body);
  eventBus.emit('user.created', { userId: user.id, email: user.email });
  res.status(201).json(user);
});

app.listen(3001, () => console.log('User Service running on :3001'));
Pro Tip
Start with a modular monolith first! Only extract microservices when team boundaries or distinct scaling demands make it necessary.

The key is not to microservice everything from day one, but to design with clear boundaries and clean APIs so the transition is smooth when scaling.

Building Scalable APIs with Node.js and GraphQL Best Practices

R
Roshan Damor
October 28, 2024

REST has served us well for decades, but as frontends grew more complex and mobile came to dominate, over-fetching and under-fetching became real pain points. GraphQL lets clients specify exact response structures in a single query.

GraphQL vs REST
GraphQL collapses 3+ REST HTTP roundtrips into a single declarative POST query while automatically generating typescript type definitions.

Schema & ER Model

GraphQL Type System & ER Schema

  • FK authorIdID!

Docker and Kubernetes: Complete Guide to Container Orchestration

R
Roshan Damor
September 12, 2024

Containers have fundamentally changed how we build, ship, and run software. Before Docker, environment mismatches caused endless bugs. Containers package your application with everything it needs: the runtime, libraries, environment variables, and config.

Container vs VM
Containers share the host OS kernel and isolate only processes & filesystems, making startup instantaneous (milliseconds vs minutes for VMs).

Kubernetes Cluster Topology & Schema

Kubernetes Topology Architecture
K8s v1.30
Ingress Controller
  • Rule api.domain.com
  • SSL Let's Encrypt
  • Target ClusterIP Service
Deployment Replicas
  • Replicas 3 Active Pods
  • Probe HTTP /healthz
  • Strategy RollingUpdate

Multi-Stage Dockerfile Blueprint

Dockerfile Docker 
# ── Build stage ───────────────────────────
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
RUN npm run build

# ── Production image ──────────────────────
FROM node:20-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
USER node
EXPOSE 3000
CMD ["node", "dist/index.js"]

Start with Docker, get comfortable building optimized images, then layer on Kubernetes for self-healing, scalable production deployments.
